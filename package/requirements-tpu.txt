# against a specific torch ABI. As of torch_tpu 0.1.1.dev20260922200612, shims

#     torch::autograd::_wrap_outputs(...)

# DELIBERATELY NOT INSTALLED: torchax and torch_xla.
#
# tpu-kernel-development's `reference_mode: "torchax"` obtains the JAX reference
# mechanically instead of having an agent hand-write it. It wants a torch the
# rest of this file cannot have:
#
#   torchax 0.0.13 builds autocast and decomposition tables at import time keyed
#   on aten overloads removed after torch 2.9 (aten.prod.dim_Dimname,
#   aten.cholesky, aten.all.dimname), so it does not import against the
#   torch>=2.13 pinned above.
#
#   torch_xla, which torchax pulls in for TPU execution, must match the torch
#   minor version, and its newest release is 2.9.0.
#
# Installing either here would tear down the torch_tpu stack the rest of the
# package runs on. So the loop probes for them and degrades instead:
# `reference_mode` falls back to "llm_port" when `import torchax` fails, which
# is the path that needs no extra dependency and is gated just as strictly.
# Running torchax mode needs its own venv with the matching pins, reached with
# `--interpreter` -- see references/tpu-kernel-development/torchax-oracle-pipeline.md.
