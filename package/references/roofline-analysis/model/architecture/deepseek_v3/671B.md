# DeepSeek V3 671B MoE Model Architecture Specification

This document details the architectural parameters, dimension shapes, and operation-level specifications for the DeepSeek V3 671B Mixture-of-Experts (MoE) model. These details are standardized to follow the conventions in [NOTATION.md]({{reference:roofline-analysis/NOTATION.md}}) for conducting roofline performance estimations.

## 1. Global Model Parameters

| Parameter | Symbol | Value | Description |
| :--- | :--- | :--- | :--- |
| **Total Parameters** | - | $\approx 671\text{B}$ | Approximate total parameters. |
| **Active Parameters** | - | $\approx 37\text{B}$ | Approximate active parameters per token. |
| **Layers** | $L$ | 61 | Total transformer layers. |
| **Hidden Dimension** | $D$ | 7,168 | Hidden dimension size (model dimension). |
| **MoE FFN Dim** | $F_{\text{expert}}$ | 2,048 | Intermediate hidden dimension per routed expert. |
| **Number of Experts** | $E$ | 256 | Total number of routed experts. |
| **Experts per Token** | $K$ | 8 | Number of routed experts activated per token. |
| **Shared Experts** | $E_{\text{shared}}$| 1 | Number of shared experts (always active). |
| **Query Heads** | $H_q$ | 128 | Number of query heads. |
| **Head Dimension** | $D_h$ | 128 | Dimension size per attention head. |
| **KV Latent Dim** | $D_c$ | 512 | Compressed latent dimension for KV cache (MLA). |
| **RoPE Dim** | $D_r$ | 64 | Decoupled RoPE dimension (MLA). |

## 2. Layer Structure & Tensor Flow

DeepSeek V3 utilizes a decoder-only Transformer architecture with Multi-Head Latent Attention (MLA) and the DeepSeekMoE architecture.

```text
[Input: B x S x D]
       |
       +- RMSNorm -> MLA Self-Attention Block -> [Attention Output] -> Add Residual
       |
       +- RMSNorm -> MoE Router 
       |             |-> Top-K Routed Experts (SwiGLU) --+
       |             |-> Shared Expert (SwiGLU) ---------+-> [FFN Output] -> Add Residual
       |
[Output: B x S x D]
```

### 2.1. Multi-Head Latent Attention (MLA) Block Operations
MLA drastically reduces the KV cache size by compressing keys and values into a single latent vector, while using a decoupled RoPE strategy.

1.  **Query Projection & Compression:** 
    *   Query is compressed to an intermediate dimension (e.g., 1536) and then projected to $H_q$ heads.
    *   A separate decoupled RoPE projection of size $D_r$ is appended.
2.  **KV Latent Compression (`W_KV_comp`):** Projects hidden dimension to the KV latent dimension $D_c$.
    *   **Weight Shape:** `[D, D_c]`
3.  **KV Decompression:** 
    *   The latent vector is projected back to Key and Value representations.
    *   A separate decoupled RoPE projection for keys is used.
4.  **Attention Core (QK^T and Score * V):**
    *   Computes attention using the reconstructed keys and values along with the decoupled RoPE.
    *   Due to matrix absorption, the up-projection matrices can be fused into the query and output projections during inference.
5.  **Output (O) Projection (`W_o`):** Projects attention heads back to hidden dimension.
    *   **Weight Shape:** `[H_q * D_h, D]`

### 2.2. FFN Block Operations (DeepSeekMoE)
The FFN block combines a MoE router, 256 fine-grained routed experts, and 1 shared expert. The shared expert is always active for every token.

1.  **Router:** Computes expert assignment probabilities.
    *   **Weight Shape:** `[D, E]`
2.  **Routed Experts Gate/Up Projection (`W_gate_up`):** Computes gating and up activations for the selected $K=8$ experts.
    *   **Weight Shape (per expert):** `[D, 2 * F_expert]`
3.  **Routed Experts Down Projection (`W_down`):** Projects intermediate dimension back to hidden dimension.
    *   **Weight Shape (per expert):** `[F_expert, D]`
4.  **Shared Expert Gate/Up Projection:** Computes gating and up activations for the shared expert.
5.  **Shared Expert Down Projection:** Projects shared intermediate dimension back to hidden dimension.
