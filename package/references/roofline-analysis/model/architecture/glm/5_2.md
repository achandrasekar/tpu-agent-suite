operation-level specifications for the GLM 5.2 model. These details are
standardized to follow the conventions in [NOTATION.md]({{reference:roofline-analysis/NOTATION.md}}) for
conducting roofline performance estimations.

## 2. Layer Structure & Tensor Flow

GLM 5.2 utilizes a decoder-only Transformer architecture that combines
Multi-Head Latent Attention (MLA), a custom Dynamic Sparse Attention (DSA)
indexer, and Mixture-of-Experts (MoE).

The model features two types of blocks:

1.  **Dense Blocks (Layers 0-2)**: DSA Attention + Dense SwiGLU FFN.
2.  **MoE Blocks (Layers 3-77)**: DSA Attention + DeepSeekMoE FFN.

```text
[Input: B x S x D]
       |
       +- RMSNorm -> DSA Attention Block (Full or Shared Indexer) -> [Attention Output] -> Add Residual
       |
       +- RMSNorm -> FFN Block
                     |-> [If Layer < 3]  Dense FFN (SwiGLU, size F) --------------------+
                     |-> [If Layer >= 3] MoE Router -> Top-8 Experts + 1 Shared Expert -+-> [FFN Output] -> Add Residual
       |
[Output: B x S x D]
```

### 2.1. Attention Block (DSA + MLA)

The attention block uses **Multi-Head Latent Attention (MLA)** for QKV
projection, but restricts the core attention calculation to the top-$K_{idx}$
tokens selected by a **Lightning Indexer** (Dynamic Sparse Attention).

#### IndexShare (Cross-Layer Index Sharing)

To reduce indexing overhead at long context lengths:

*   **Computing Layers ("full")**: Layers where `(max(layer_idx - 2, 0) % 4) ==
    0` (where `layer_idx` is 0-indexed: layers 0, 1, 2, 6, 10, ...). These
    layers run the active indexer to select top-k tokens.
*   **Skip Layers ("shared")**: All other layers. These layers bypass the
    indexer calculation and reuse the `topk_indices` from the most recent
    computing layer.

#### Operations:

1.  **Query Projection & RMSNorm**:
    *   Compresses hidden states to $D_{c,q}$ (2048): `[B, S, D] -> [B, S,
        D_c_q]`.
    *   Projects latent representation to $H_q$ heads of size $D_{nope} = 192$:
        `[B, S, H_q * D_nope]`.
    *   Separate decoupled RoPE projection of size $D_r = 64$: `[B, S, H_q *
        D_r]`.
2.  **KV Latent Compression**: Projects hidden dimension to the KV latent
    dimension $D_c = 512$: `[B, S, D_c]`.
3.  **KV Latent Decompression**:
    *   Non-RoPE Keys: Projected from latent $D_c$ to $H_q \times D_{nope}$
        (using $W_{kb}$ shape `[D_c, H_q * D_nope]`).
    *   Values: Projected from latent $D_c$ to $H_q \times D_v$ (using $W_{vb}$
        shape `[D_c, H_q * D_v]`).
    *   RoPE Keys: $k_{rot}$ (already projected in step 2 to shape `[B, S,
        D_r]`) is expanded to `[B, H_q, S, D_r]`.
4.  **Lightning Indexer (Computing Layers only)**:
    *   Projects query latent $D_{c,q}$ to indexer query space: `[B, S, H_idx *
        D_idx]`.
    *   Projects hidden states to indexer key space: `[B, S, D_idx]`.
    *   Applies **interleaved** RoPE to indexer queries and keys.
    *   Computes raw logits: `ReLU(q_idx @ k_idx^T)`.
    *   Projects hidden states to head weights `[B, S, H_idx]`, scales, and
        aggregates logits across heads to get score `[B, S, T]` (where T is the
        history key sequence length).
    *   Applies causal mask and selects top-$K_{idx}$ token indices.
5.  **Sparse Attention Core**:
    *   Computes QK attention and AV values **only** for the selected $K_{idx}$
        tokens per query.
    *   During inference, weight absorption is used to fuse key/value
        decompression into the query and output projections.
6.  **Output (O) Projection**: Projects fused attention output back to hidden
    dimension: `[B, S, H_q * D_h] -> [B, S, D]`.

### 2.2. FFN Block (SwiGLU)

#### Dense FFN (Layers 0-2)

A standard Gated MLP (SwiGLU) with intermediate size $F = 12288$:

*   `Gate/Up` projection shape: `[D, 2 * F]`
*   `Down` projection shape: `[F, D]`

#### MoE FFN (Layers 3-77)

Uses DeepSeekMoE routing with 1 shared expert and 256 routed experts (Top-8
active per token), all experts use SwiGLU with size $F_{\text{expert}} = 2048$:

1.  **Router**: Computes sigmoid gating scores for 256 experts: `[B * S, E]`.
2.  **Routed Experts**:
    *   Each token is routed to $K = 8$ experts.
    *   `Gate/Up` projection per expert: `[D, 2 * F_expert]`
    *   `Down` projection per expert: `[F_expert, D]`
3.  **Shared Expert**:
    *   All tokens are unconditionally processed by the shared expert.
    *   `Gate/Up` projection: `[D, 2 * (F_expert * E_shared)]`
    *   `Down` projection: `[(F_expert * E_shared), D]`
