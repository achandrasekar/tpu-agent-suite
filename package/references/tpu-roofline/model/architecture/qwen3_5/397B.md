# Qwen3.5-397B-A17B Model Architecture Specification

This document details the architectural parameters, dimension shapes, and operation-level
specifications for **`Qwen/Qwen3.5-397B-A17B-FP8`** — this repo's flagship benchmark model. All
symbols follow [NOTATION.md](../../../NOTATION.md) for use in roofline performance estimation.

**Sources.** Every hyperparameter below is read from the checkpoint's own `config.json`, fetched
from `https://huggingface.co/Qwen/Qwen3.5-397B-A17B-FP8/raw/main/config.json`.
Layer structure and fusion layout are read from the vLLM implementation:

*   `vllm/model_executor/models/qwen3_5.py` — `Qwen3_5DecoderLayer`, `Qwen3_5Model`
*   `vllm/model_executor/models/qwen3_next.py` — `Qwen3NextAttention`, `Qwen3NextSparseMoeBlock`
*   `vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py` — `QwenGatedDeltaNetAttention`

> [!IMPORTANT]
> **Scope: the text decoder.** The checkpoint is multimodal and also ships a Multi-Token Prediction
> head; neither is on the path the benchmarks measure. See [§6](#6-out-of-scope-modules-vision-tower--mtp-head).

## 2. Layer Structure & Tensor Flow

Qwen3.5-397B is a **hybrid linear/softmax attention** model in which *every* layer is MoE.

*   **Attention sub-layers (3:1 interleaving, `full_attention_interval = 4`):**
    *   3 GDN linear-attention layers followed by 1 gated GQA layer, repeated 15 times.
    *   **GQA layers (0-indexed, 15 total):** $\{3, 7, 11, \ldots, 59\}$, i.e. every layer with
        $\ell \bmod 4 = 3$.
    *   **GDN layers (0-indexed, 45 total):** all remaining layers.
    *   *This is read directly from the explicit 60-entry `layer_types` list, not inferred from the
        interval.* The list ends on a `full_attention` layer (59).
*   **FFN sub-layers:** all 60 layers are `Qwen3NextSparseMoeBlock` — Top-10 of 512 routed experts
    ($F_{\text{expert}} = 1{,}024$) **plus** 1 always-on shared expert
    ($F_{\text{shared}} = 1{,}024$) gated by a scalar sigmoid.
*   **Residual/norm:** standard pre-norm. `input_layernorm` (RMSNorm) before attention,
    `post_attention_layernorm` (RMSNorm) before the MoE block, plain additive residuals.
    `layer_scale` is not set in this checkpoint.

```text
[Input: B x S x D = B x S x 4096]
       |
       +---> RMSNorm (input_layernorm)
       |
       +---> Attention Sub-Layer:
       |     ├── If GDN layer (45):  in_proj_qkv + in_proj_z + in_proj_b + in_proj_a
       |     |                       -> Conv1D(K=4, SiLU) -> L2Norm(q,k)
       |     |                       -> Gated Delta Rule kernel -> Gated RMSNorm(z)
       |     |                       -> out_proj [RowParallel -> TP All-Reduce]
       |     └── If GQA layer (15):  qkv_proj (Q | gate | K | V, fused)
       |                             -> QK-RMSNorm -> partial RoPE (64 of 256)
       |                             -> Causal FlashAttention (paged KV, fp8 cache)
       |                             -> sigmoid(gate) * attn_out
       |                             -> o_proj [RowParallel -> TP All-Reduce]
       |
       +---> Add attention residual
       |
       +---> RMSNorm (post_attention_layernorm)
       |
       +---> MoE Sub-Layer (all 60 layers):
       |     ├── Router: [4096, 512] -> Top-10, renormalized
       |     ├── Routed experts: 512 x SwiGLU(4096 -> 1024 -> 4096), fp8 block-quantized
       |     └── Shared expert: 1 x SwiGLU(4096 -> 1024 -> 4096), scalar sigmoid gate
       |         (parallel branch on the same input; summed with the routed output)
       |
       +---> Add MoE residual
       |
[Output: B x S x D]
```

## 3. Sub-Component Operations & Tensor Shapes

### 3.1. Gated Delta Network (GDN) Sub-Layer — 45 Layers

Refer to the [GDN Roofline Skill](../../common/attention/gdn/gdn.md) for the full operational
formulas; that skill's worked example *is* this model. Note that here
$D_k = D_v = 128$, so the skill's `H_v * D_h_qk` and $H_v D_v$ coincide numerically.

#### 1. QKV Projection (`in_proj_qkv`)

*   Weight: $[D,\ 2 H_{qk} D_k + H_v D_v] = [4096,\ 12288]$. Column-parallel.
*   Splits as `q` (2,048) | `k` (2,048) | `v` (8,192) — exactly $D_{\text{conv}}$, since all three
    go through the convolution.
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (2 H_{qk} D_k + H_v D_v)$.

#### 2. Z / B / A Gate Projections (`in_proj_z`, `in_proj_b`, `in_proj_a`)

Qwen3.5 ships these as **three separate checkpoint tensors** (Qwen3-Next pre-fuses them into
`in_proj_qkvz` / `in_proj_ba`; `Qwen3_5Model.hf_to_vllm_mapper` fuses them at load time). For
roofline purposes they are one column-parallel GEMM of combined width
$H_v D_v + 2 H_v = 8{,}192 + 128 = 8{,}320$, matching the GDN skill's ZBA projection.

*   **`in_proj_z`** (RMSNorm gate): $[D,\ H_v D_v] = [4096,\ 8192]$.
*   **`in_proj_b`** (write rate $\beta$): $[D,\ H_v] = [4096,\ 64]$.
*   **`in_proj_a`** (decay $\alpha$): $[D,\ H_v] = [4096,\ 64]$.
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (H_v D_v + 2 H_v)$.
*   Combined with `A_log` $[H_v]$ and `dt_bias` $[H_v]$, the decay is
    $g = -\exp(\texttt{A\_log}) \cdot \operatorname{softplus}(a + \texttt{dt\_bias})$ — negligible FLOPs.

#### 3. Causal Depthwise 1D Convolution + SiLU

Refer to the [Conv1D Roofline Skill](../../common/conv1d/conv1d.md).

*   $D_{\text{conv}} = 12{,}288$, $K_{\text{conv}} = 4$, SiLU activation, depthwise
    (`groups = D_conv`). Weight $[D_{\text{conv}}, 1, K_{\text{conv}}]$ plus a bias
    $[D_{\text{conv}}]$.
*   **Prefill FLOPs:** $2 B_{\text{local}} S \cdot D_{\text{conv}} \cdot K_{\text{conv}}$.
*   **Decode conv state:** $[B_{\text{local}},\ K_{\text{conv}} - 1,\ D_{\text{conv}}]$
    $= [B_{\text{local}}, 3, 12288]$.

#### 4. Gated Delta Rule Kernel

Applied after **L2 normalization of $q$ and $k$** (`l2norm_fwd`, `use_qk_l2norm_in_kernel=True`).
See the GDN skill [§4](../../common/attention/gdn/gdn.md) for prefill (chunk-wise) and decode
(recurrent) formulas.

*   **Recurrent state:** $[B_{\text{local}},\ H_v,\ D_k,\ D_v] = [B_{\text{local}}, 64, 128, 128]$,
    held in **`float32`** (`mamba_ssm_dtype: "float32"`) — $4.0\text{ MiB}$ per sequence per layer.
*   **Decode FLOPs:** $7 B_{\text{local}} H_v D_k D_v \approx 7.34\ B_{\text{local}}\text{ MFLOPs}$
    per layer per step.

> [!NOTE]
> **On the chunk size $C$.** The GDN component skill takes $C = 64$ as typical. The `vllm-torchtpu`
> v3 GDN kernel does **not** hardcode it: `kernels/gdn/v3/config.py` derives `chunk_size` from
> `tile_size` in `PER_SEQ` mode and from `window_size` otherwise, and falls back to a token-recurrent
> scan when `chunk_size == 1`. Read the value being used rather than assuming 64, and state which
> you used.

#### 5. Gated RMSNorm

*   `RMSNormGated(head_v_dim=128)` with **SiLU** activation (`output_gate_type` defaults to `silu`).
    $o = \operatorname{SiLU}(z) \odot \operatorname{RMSNorm}(u)$, applied per V head.
*   Shapes: `core_attn_out` and $z$ both $[B_{\text{local}}, S, H_v D_v]$.

#### 6. Output Projection (`out_proj`)

Refer to the [Output Projection Skill](../../common/attention/out_proj/out_proj.md).

*   Weight: $[H_v D_v,\ D] = [8192,\ 4096]$. Row-parallel → **TP All-Reduce** of payload
    $B_{\text{local}} S D \times \text{bytes}$.
*   **FLOPs:** $2 B_{\text{local}} S \cdot H_v D_v \cdot D$.

> [!NOTE]
> When `use_sequence_parallel_moe` is on and PP = 1, `reduce_results` is disabled on `out_proj` and
> the collective becomes a **Reduce-Scatter** into the sequence-parallel MoE block instead of an
> All-Reduce (`Qwen3_5DecoderLayer.use_attn_reduce_scatter_for_moe`). Confirm which is active before
> costing the collective.

### 3.2. Gated Full Attention (GQA) Sub-Layer — 15 Layers

Refer to the [QKV Projection](../../common/attention/qkv_proj/qkv_proj.md),
[Global Attention](../../common/attention/global_attention/global_attention.md) and
[Output Projection](../../common/attention/out_proj/out_proj.md) skills.

> [!WARNING]
> **This layer deviates from the plain GQA the `qkv_proj` skill models.** Two differences change the
> arithmetic and must not be dropped:
>
> 1.  **Output gate fused into QKV.** `Qwen3NextAttention` builds `QKVParallelLinear` with
>     `total_num_heads * (1 + attn_output_gate)` query heads. The fused width is therefore
>     $(A_{\text{gate}} H_q + 2 H_{kv}) D_h = (2 \cdot 32 + 2 \cdot 2) \cdot 256 = 17{,}408$,
>     **not** the skill's $(H_q + 2H_{kv})D_h = 9{,}216$. The QKV projection costs $1.89\times$ the
>     un-gated version.
> 2.  **Partial RoPE.** Only $D_{\text{rope}} = 64$ of each head's $D_h = 256$ channels are rotated.
>     This does not change the QK/AV FLOPs, but it does change the RoPE op's own cost.

#### 1. Fused QKV + Gate Projection (`qkv_proj`)

*   Weight: $[D,\ (A_{\text{gate}} H_q + 2 H_{kv}) D_h] = [4096,\ 17408]$. Column-parallel.
*   Splits as `q` (8,192) | `gate` (8,192) | `k` (512) | `v` (512).
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (A_{\text{gate}} H_q + 2 H_{kv}) D_h$.
*   Of which the gate ($W_{\text{gate}}$, per [NOTATION.md](../../../NOTATION.md)) accounts for
    $2 B_{\text{local}} S \cdot D \cdot H_q D_h$ — $8{,}192$ of the $17{,}408$ output columns,
    i.e. **47.1%** of this GEMM.

#### 2. Q/K Normalization and Partial RoPE

*   `q_norm`, `k_norm`: per-head `RMSNorm(D_h = 256)`, applied before RoPE.
*   RoPE rotates the first $D_{\text{rope}} = 64$ channels of each head only.
    FLOPs $\approx 3 B_{\text{local}} S (H_q + H_{kv}) D_{\text{rope}}$ — negligible, but the
    activation traffic is over the full $D_h$.

#### 3. Causal Attention (paged / FlashAttention)

*   Q: $[B_{\text{local}}, S, H_q, D_h]$; K/V cache: $[B_{\text{local}}, S_{\text{kv}}, H_{kv}, D_h]$.
*   **Prefill (causal) FLOPs:** QK phase $B_{\text{local}} S^2 H_q D_h$; AV phase
    $B_{\text{local}} S^2 H_q D_h$.
*   **Decode FLOPs ($S = 1$):** QK $2 B_{\text{local}} S_{\text{kv}} H_q D_h$; AV
    $2 B_{\text{local}} S_{\text{kv}} H_q D_h$.
*   **KV cache footprint:** $2 \cdot H_{kv} \cdot D_h = 1{,}024$ elements per token per GQA layer.
    See [§4.3](#43-kv-cache-and-recurrent-state-footprint).

#### 4. Output Gating

*   $\text{attn\_out} \leftarrow \sigma(\text{gate}) \odot \text{attn\_out}$, elementwise over
    $[B_{\text{local}}, S, H_q D_h]$. FLOPs $O(B_{\text{local}} S H_q D_h)$; fusible.

#### 5. Output Projection (`o_proj`)

*   Weight: $[H_q D_h,\ D] = [8192,\ 4096]$. Row-parallel → **TP All-Reduce** (same
    Reduce-Scatter caveat as [§3.1.6](#6-output-projection-out_proj)).
*   **FLOPs:** $2 B_{\text{local}} S \cdot H_q D_h \cdot D$.

### 3.3. Sparse MoE Sub-Layer — All 60 Layers

Refer to the [MoE Roofline Skill](../../common/moe/moe.md). Both branches consume the same
`post_attention_layernorm` output; their outputs are summed.

#### 1. Router (`mlp.gate`)

*   Weight: $[D,\ E] = [4096,\ 512]$, **`bf16`** (excluded from fp8; `ReplicatedLinear` with
    `quant_config=None`). Replicated across devices — no collective.
*   Top-$K$ = 10, routing weights renormalized. (`norm_topk_prob` is **absent** from this
    `config.json`; vLLM reads it as `getattr(config, "norm_topk_prob", True)`, so renormalization
    is the code default rather than a checkpoint setting. Either way it is negligible FLOPs.)
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot E$.

#### 2. Routed Experts (512 experts, Top-10, SwiGLU)

*   **W1 gate/up (fused):** per expert $[D,\ 2 F_{\text{expert}}] = [4096,\ 2048]$.
    **FLOPs:** $4 B_{\text{local}} S K \cdot D \cdot F_{\text{expert}}$.
*   **Activation:** SiLU-GLU (`hidden_act: "silu"`).
*   **W2 down:** per expert $[F_{\text{expert}},\ D] = [1024,\ 4096]$.
    **FLOPs:** $2 B_{\text{local}} S K \cdot F_{\text{expert}} \cdot D$.
*   **Total routed FLOPs:** $6 B_{\text{local}} S K \cdot D \cdot F_{\text{expert}}$.
*   **Weight bytes per layer:** $E \cdot 3 \cdot D \cdot F_{\text{expert}} = 6.44\text{ G}$
    parameters at **1 byte** (fp8) $= 6.44\text{ GB}$, divided by EP. This is the dominant HBM
    term at low batch — see [§4.2](#42-arithmetic-intensity-of-the-routed-expert-gemms).
*   **Note the aspect ratio.** $F_{\text{expert}} = 1{,}024$ against $D = 4{,}096$ makes each
    expert GEMM narrow; combined with 512 experts this is a many-small-GEMM (grouped/ragged)
    problem, not one large one. The benchmark configs set `USE_MOE_SPARSE_CORE=1` and
    `ONEHOT_MOE_PERMUTE_THRESHOLD=32768`, both of which target the routing/permute path; the
    connection to this shape is inferred from the flag names, not from a documented rationale.

#### 3. Shared Expert (1, always active)

*   `shared_expert_gate`: $[D, 1]$, **`bf16`**, scalar sigmoid applied to the shared branch output.
*   **W1 gate/up:** $[D,\ 2 F_{\text{shared}}] = [4096,\ 2048]$;
    **W2 down:** $[F_{\text{shared}},\ D] = [1024,\ 4096]$.
*   **FLOPs:** $6 B_{\text{local}} S \cdot D \cdot F_{\text{shared}}$ (no $K$ factor).
*   Per the MoE skill, the shared expert uses **TP even when the routed experts use EP**. vLLM may
    additionally fuse it into the `FusedMoE` op (`maybe_fuse_shared_experts`, `n_shared_experts=1`),
    which removes a separate GEMM launch but not its FLOPs.

## 4. Precision, Quantization & Memory Footprint

### 4.1. Data Types

`quantization_config`: `quant_method: "fp8"`, **block-wise `[128, 128]`**,
`activation_scheme: "dynamic"`, `weight_per_tensor: false`, `act_per_tensor: false`.

The `modules_to_not_convert` list is perfectly regular across all 60 layers — verified by
classifying all 60 entries, which collapse to exactly two sets:

| Scope | Modules kept in `bf16` |
| :--- | :--- |
| All 45 GDN layers | `linear_attn.conv1d`, `linear_attn.in_proj_a`, `linear_attn.in_proj_b`, `mlp.gate`, `mlp.shared_expert_gate` |
| All 15 GQA layers | `mlp.gate`, `mlp.shared_expert_gate` |
| Global | `lm_head`, `embed_tokens`, the entire vision tower, `mtp.fc`, `mtp.layers.0.mlp.{gate,shared_expert_gate}` |

Everything else — **including `in_proj_qkv`, `in_proj_z`, `out_proj`, `qkv_proj`, `o_proj`, all
routed-expert and shared-expert weights** — is fp8 at 1 byte per parameter.

*   **Weights (fp8 path):** `float8` (1 B/param) + a `float32` scale per $128 \times 128$ block
    (an $\approx 0.024\%$ byte overhead; usually ignorable, but state it if you include it).
*   **Weights (bf16 path):** 2 B/param, per the table above.
*   **Activations:** `bfloat16` (`dtype: "bfloat16"`), dynamically cast to fp8 at each quantized
    GEMM. MXU accumulation is `float32` — see [TYPE_PROMOTION.md](../../../TYPE_PROMOTION.md).
*   **GDN recurrent state:** **`float32`** (`mamba_ssm_dtype: "float32"`), 4 B/element.
*   **GDN conv state:** `bfloat16`, 2 B/element.
*   **GQA KV cache:** `KV_CACHE_DTYPE="fp8"` in every `qwen3.5-397b-*` benchmark config → **1
    B/element**. This is a *serving flag, not a checkpoint property* — confirm it from the
    `VLLM_SERVER_CMD` for the job you are modelling rather than assuming it.

### 4.2. Arithmetic intensity of the routed-expert GEMMs

> [!NOTE]
> Everything in this subsection is **modelled**, not measured. It is an analytic bound on where the
> memory/compute crossover sits, useful for ranking candidates; it is not a benchmark result and
> must never be quoted as one.

The routed experts dominate both the parameter count and the HBM traffic, and their arithmetic
intensity is set entirely by the *number* of local tokens — not by how those tokens split between
batch and sequence, and not by $D$ or $F_{\text{expert}}$, which cancel. Using the
[MoE skill](../../common/moe/moe.md)'s EP formulas with
$N_{\text{local}} = B_{\text{local}} S$ local tokens:

$$\text{AI} \;=\; \frac{6 N_{\text{local}} K D F_{\text{expert}}}{(E/\text{EP}) \cdot 3 D F_{\text{expert}} \cdot 1\text{ B}} \;=\; \frac{2 N_{\text{local}} K \cdot \text{EP}}{E}$$

At $K = 10$, $E = 512$, $\text{EP} = 8$ this is $0.3125$ FLOP/byte per local token. Against the
per-chiplet machine balance from the TPU7x knowledge-base page `hw-tpu-7x`, obtained through tpu-knowledge-base (per-chip figures / 2):

| Peak used | FLOPS | Balance point | Crossover $N_{\text{local}}$ |
| :--- | ---: | ---: | ---: |
| FP8 | $2{,}307\text{ TFLOPS}$ | $625.2$ FLOP/B | $\approx 2{,}001$ tokens |
| BF16 | $1{,}153.5\text{ TFLOPS}$ | $312.6$ FLOP/B | $\approx 1{,}000$ tokens |

(HBM $= 3{,}690\text{ GB/s}$ per chiplet. Weight bytes per device per layer are
$(E/\text{EP}) \cdot 3 D F_{\text{expert}} = 805\text{ MB}$, giving a fixed $0.218\text{ ms}$
HBM floor per layer regardless of token count; activation traffic is excluded, so these
crossovers are an *upper* bound on AI and therefore a *lower* bound on the crossover.)

So a decode step at $S = 1$ needs $B_{\text{local}}$ in the **thousands** — not the hundreds —
before the routed MoE stops being memory bound. Below that the GEMMs read the entire local expert
bank to do almost no arithmetic. Model the decode MoE as **memory bound** unless the local token
count says otherwise, and recompute the intensity for the actual $K$, $E$ and EP of the job rather
than reusing the table above.

> [!NOTE]
> **MXU contracting-dimension padding.** [REQUIREMENTs.md](../../common/REQUIREMENTs.md) requires
> ceil-padding any contracting dimension below the v7x minimum of **256**. Across the whole text
> decoder the only dimensions that fall below it are the GDN kernel's $D_k = D_v = 128$
> ([§3.1.4](#4-gated-delta-rule-kernel)); every other contraction is $\ge 256$ ($D = 4{,}096$ for
> the projections and the router, $F_{\text{expert}} = F_{\text{shared}} = 1{,}024$ for the down
> projections, $D_h = 256$ exactly for the GQA QK phase). Apply the padding rule to the delta-rule
> matmul terms and say whether you did.

### 4.3. KV Cache and Recurrent State Footprint

For one sequence at context length $S$:

1.  **GQA KV cache (15 layers):**
    $$L_{\text{gqa}} \cdot S \cdot 2 H_{kv} D_h \cdot b_{\text{kv}} = 15 \cdot S \cdot 1024 \cdot b_{\text{kv}}$$
    At $b_{\text{kv}} = 1$ B (fp8): $15{,}360\text{ B} = \mathbf{15.0\text{ KiB per token}}$ — e.g.
    $\approx 2.01\text{ GB}$ at $S = 131{,}072$. At `bf16` it doubles.
2.  **GDN recurrent state (45 layers), $O(1)$ in $S$:**
    $$L_{\text{gdn}} \cdot H_v D_k D_v \cdot 4\text{ B} = 45 \cdot 64 \cdot 128 \cdot 128 \cdot 4 = \mathbf{188.7\text{ MB per sequence}}$$
3.  **GDN conv state (45 layers), $O(1)$ in $S$:**
    $$L_{\text{gdn}} \cdot (K_{\text{conv}} - 1) \cdot D_{\text{conv}} \cdot 2\text{ B} = 45 \cdot 3 \cdot 12288 \cdot 2 = \mathbf{3.32\text{ MB per sequence}}$$

> [!IMPORTANT]
> The $192\text{ MB}$ of $S$-independent GDN state per sequence is a **fixed per-slot cost**: it is
> paid in full whether the sequence is 100 tokens or 100K. Below roughly $S \approx 12.5\text{K}$
> it exceeds the fp8 KV cache. This is what bounds concurrency at short context, and it is the
> opposite of the usual "KV cache dominates" intuition — do not carry that intuition into a
> `max_num_seqs` estimate for this model. See the
> [Memory Usage Skill](../../../memory_usage/memory_usage.md).

## 6. Out-of-Scope Modules: Vision Tower & MTP Head

Recorded so that a reader knows they exist, not modelled here.

*   **Vision tower** (`vision_config`): 27 blocks, $d = 1{,}152$, intermediate $4{,}304$, 16 heads,
    patch 16, temporal patch 2, spatial merge 2, projecting to `out_hidden_size = 4096`.
    $\approx 0.45\text{ B}$ parameters, entirely `bf16` (all `model.visual.*` are in
    `modules_to_not_convert`). **Every `qwen3.5-397b-*` benchmark config serves with
    `--language-model-only` and `--limit-mm-per-prompt {"image":0,"video":0}`**, so the tower is
    not instantiated on the measured path. Ignore it unless you are explicitly modelling
    multimodal prefill.
*   **MTP head** (`mtp_num_hidden_layers: 1`, `mtp_use_dedicated_embeddings: false`): one extra
    decoder layer plus an `mtp.fc`, for speculative decoding. Present in the checkpoint; **not
    enabled** by the benchmark configs (no speculative-decoding arguments), so it contributes no
    FLOPs and no HBM traffic on the measured path. If a job does enable it, it adds roughly one
    more MoE decoder layer's cost per verified token.

## 7. Parallelism Strategies

The three nightly layouts in `vllm-torchtpu/scripts/vllm/benchmarking/configs/` all run
$\text{TP} \times \text{DP} = 8$ with `ENABLE_EP=true`, `QUANTIZATION="fp8"` and
`KV_CACHE_DTYPE="fp8"`: `qwen3.5-397b-fp8-tp1-dp8-ep.sh` (**the golden layout**),
`-tp2-dp4-ep.sh`, `-tp8-dp1-ep.sh`. A world size of 8 fits the single-node `tpu7x` 2x2x1 recipe
(4 chips / 8 chiplets), but the config files set only TP and DP — the topology comes from the
job recipe, not from them.

> [!IMPORTANT]
> Read TP/DP/EP **and the topology** back from the job recipe for the job you are modelling
> (`--tensor-parallel-size`, `--data-parallel-size`, `--enable-expert-parallel`). A typo'd recipe
> key falls back to the recipe default silently.

### 7.1. Tensor Parallelism (TP)

*   **GDN:** $H_{qk,\text{local}} = H_{qk}/\text{TP}$, $H_{v,\text{local}} = H_v/\text{TP}$;
    $D_{\text{conv},\text{local}} = D_{\text{conv}}/\text{TP}$. The conv is depthwise and the delta
    kernel is per-head, so **no collective occurs inside the GDN kernel**. `in_proj_*` are
    column-parallel; `out_proj` is row-parallel with the All-Reduce.
*   **GQA:** $H_{q,\text{local}} = 32/\text{TP}$. **$H_{kv} = 2$, so at $\text{TP} > 2$ the KV heads
    are replicated, not sharded**: `num_kv_heads = max(1, 2 // TP) = 1` for $\text{TP} \in
    \{4, 8\}$, with each unique head held by $\text{TP}/2$ ranks. The KV cache does **not** shrink
    past $\text{TP} = 2$ — a `tp8-dp1` layout stores 4× the aggregate KV bytes that head-count
    scaling would suggest. The gate shards with Q.
*   **MoE:** router replicated; shared expert sharded on $F_{\text{shared}}$; the attention
    All-Reduce and the MoE All-Reduce are separate collectives unless fused.

### 7.2. Expert Parallelism (EP)

*   512 routed experts partitioned evenly: $E_{\text{local}} = 512 / \text{EP}$ (64 per device at
    $\text{EP} = 8$), i.e. $805\text{ MB}$ of fp8 expert weights per device per layer.
*   **Default collective strategy is Option B (Replicated-Input EP)** per the
    [MoE skill](../../common/moe/moe.md): All-Gather of $B S D \times \text{bytes}$ before the
    experts, Reduce-Scatter (or All-Reduce) after. Dispatch-based All-to-All is for training or on
    explicit instruction only.
