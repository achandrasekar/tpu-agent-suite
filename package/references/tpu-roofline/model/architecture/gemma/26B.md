# Gemma4 26B A4B MoE Model Architecture Specification

This document details the architectural parameters, dimension shapes, and operation-level specifications for the Gemma4 26B A4B Mixture-of-Experts (MoE) model. These details are standardized to follow the conventions in [NOTATION.md](../../../NOTATION.md) for conducting roofline performance estimations.

## 2. Layer Structure & Tensor Flow

Each transformer layer contains a Self-Attention block and a Feed-Forward Network (FFN) block. The FFN block is a Mixture-of-Experts (MoE) block with a parallel shared expert.

```text
[Input: B x S x D]
       |
       +- RMSNorm -> Self-Attention Block -> [Attention Output] -> Add Residual
       |
       +- RMSNorm -> MoE Router 
       |             |-> Top-K Routed Experts (SwiGLU) --+
       |             |-> Shared Expert (SwiGLU) ---------+-> [FFN Output] -> Add Residual
       |
[Output: B x S x D]
```

### 2.1. Self-Attention Block Operations
The attention block utilizes Grouped-Query Attention (GQA) sharded via Tensor Parallelism with degree $P$:

1.  **Q Projection (`W_q`):** Projects hidden dimension to local query heads.
    *   **Weight Shape:** `[D, (H_q / P) * D_h]`
2.  **K Projection (`W_k`):** Projects hidden dimension to key heads.
    *   **Weight Shape (Local):** `[D, max(1, H_kv_local / P) * D_h]`
    *   **Weight Shape (Global):** `[D, max(1, H_kv_global / P) * D_h_global]` (where $D_h\_global$ = 512)
3.  **V Projection (`W_v`):** Projects hidden dimension to value heads.
    *   **Weight Shape (Local):** Same as K Projection.
    *   **Note (Global):** In Global layers only, K and V share the exact same weights ($W_k = W_v$), meaning only a single projection is computed.
4.  **Attention Core (QK^T and Score * V):**
    *   **QK Phase:** Computes attention matrix.
    *   **AV Phase:** Computes output attention context.
5.  **Output (O) Projection (`W_o`):** Projects attention heads back to hidden dimension.
    *   **Weight Shape:** `[(H_q / P) * D_h, D]`
    *   **Collective:** All-Reduce along the parallel dimension $P$ (typically BF16).

### 2.2. FFN Block Operations (MoE + Shared Expert)
The FFN block combines a MoE router, $E$ routed experts, and a shared expert. Experts are typically partitioned across devices (Expert Parallelism).
*Note: The 26B model has fused gating + up projections in the MoE blocks.*

1.  **Router:** Computes expert assignment probabilities.
    *   **Weight Shape:** `[D, E]`
2.  **Routed Experts Gate/Up Projection (`W_gate_up`):** Computes gating and up activations for the selected $K$ experts.
    *   **Weight Shape (per device):** `[E / P, D, 2 * F_expert]` (fused gate and up)
3.  **Routed Experts Down Projection (`W_down`):** Projects intermediate dimension back to hidden dimension.
    *   **Weight Shape (per device):** `[E / P, F_expert, D]`
4.  **Shared Expert Gate/Up Projection (`W_shared_gate_up`):** Computes gating and up activations for the shared expert (Tensor Parallelism).
    *   **Weight Shape:** `[D, 2 * F_shared / P]` (fused gate and up)
5.  **Shared Expert Down Projection (`W_shared_down`):** Projects shared intermediate dimension back to hidden dimension.
    *   **Weight Shape:** `[F_shared / P, D]`

## 3. Exact Shapes by Phase (P=2 Example)

Below are the tensor shapes on each device/chiplet for Parallelism $P=2$ (Tensor Parallel for dense, Expert Parallel for experts, assuming perfect load balancing):

### 3.1. Prefill Phase ($B=16, S=1024$)
*   **Input / Output Activation `[B * S, D]`:** `[16384, 2816]`.
*   **Q Proj Output `[B * S, (H_q / P) * D_h]`:** `[16384, 2048]` (8 heads on device).
*   **Local K/V Proj Output `[B * S, max(1, H_kv_local / P) * D_h]`:** `[16384, 1024]` (4 heads on device).
*   **Global K/V Proj Output `[B * S, max(1, H_kv_global / P) * D_h_global]`:** `[16384, 512]` (1 head on device, head dim 512).
*   **Attention QK Logits:** `[B, H_q / P, S, S]` which is `[16, 8, 1024, 1024]` (fused in SRAM).
*   **Attention Output `[B, S, H_q / P, D_h]`:** `[16, 1024, 8, 256]` $\rightarrow$ Projected to `[16384, 2816]`.
*   **Router Output `[B * S, E]`:** `[16384, 128]`.
*   **Routed Expert Gate/Up Input `[Total Routed Tokens per device, D]`:** `[(16384 * 8) / 2, 2816]` = `[65536, 2816]`.
*   **Routed Expert Gate/Up Output `[Total Routed Tokens per device, F_expert]`:** `[65536, 704]`.
*   **Routed Expert Down Output `[Total Routed Tokens per device, D]`:** `[65536, 2816]`.
*   **Shared Expert Gate/Up Output (after SwiGLU) `[B * S, F_shared / P]`:** `[16384, 1056]`.
*   **Shared Expert Down Output `[B * S, D]`:** `[16384, 2816]`.

### 3.2. Decode Phase ($B=256, S=1$, Context $S_{\text{ctx}}=1524$)
*   **Input / Output Activation `[B * S, D]`:** `[256, 1, 2816]`.
*   **Q Proj Output `[B * S, (H_q / P) * D_h]`:** `[256, 1, 2048]`.
*   **Local K/V Proj Output `[B * S, max(1, H_kv_local / P) * D_h]` (new token):** `[256, 1, 1024]`. (Appended to cache).
*   **Global K/V Proj Output `[B * S, max(1, H_kv_global / P) * D_h_global]` (new token):** `[256, 1, 512]`. (Appended to cache).
*   **KV Cache Read (QK phase):**
    *   Local `[B, max(1, H_kv_local / P), W, D_h]`:** `[256, 4, 1024, 256]`.
    *   Global `[B, max(1, H_kv_global / P), S_{\text{ctx}}, D_h_global]`:** `[256, 1, 1524, 512]`.
*   **Attention Output `[B, S, (H_q / P) * D_h]`:** `[256, 1, 2048]`.
*   **Router Output `[B * S, E]`:** `[256, 128]`.
*   **Routed Expert Gate/Up Input `[Total Routed Tokens per device, D]`:** `[(256 * 8) / 2, 2816]` = `[1024, 2816]`.
*   **Routed Expert Gate/Up Output `[Total Routed Tokens per device, F_expert]`:** `[1024, 704]`.
*   **Shared Expert Gate/Up Output (after SwiGLU) `[B * S, F_shared / P]`:** `[256, 1, 1056]`.
*   **Shared Expert Down Input `[B * S, F_shared / P]`:** `[256, 1, 1056]`.
